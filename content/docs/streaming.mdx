Streaming is how **`SemanticEvent<T>`** moves through the environment. Alongside **messages** (`string`) and **`ContextItem`s** (completed model/tool artifacts), semantic events are the third exchangeable event kind: incremental provider payloads with a `type` and `data`, delivered while inference is still running.

When streaming is enabled, `OpenAIInferenceRunner` yields `SemanticEvent` instances from its async generator. `BaseAgent` delivers each one on the bus — `onInternalEvent` on the producer, `onExternalEvent(source, event)` on everyone else. Custom `InferenceRunner` implementations can yield semantic events the same way.

## Enable streaming

Enable streaming on a model that supports it, then run inference as usual:

```ts
const model = new Gpt54Mini();
model.setStreaming(true);

await agent.runInference(environment, context, model);
```

Each yielded event is a **`SemanticEvent<T>`** — `event.type` names the provider event, `event.data` carries the payload. Use the handlers to drive a live UI — for example, print text deltas from `response.output_text.delta` events:

```ts
import { BaseAgent, Participant } from '@mozaik-ai/core';

export class LiveUIAgent extends BaseAgent {
  // SemanticEvent<T>: type + data from the provider stream
  async onInternalEvent(event: { type: string; data: unknown }): Promise<void> {
    if (event.type === 'response.output_text.delta') {
      process.stdout.write(String((event.data as { delta?: string }).delta ?? ''));
    }
  }

  async onExternalEvent(
    source: Participant,
    event: { type: string; data: unknown },
  ): Promise<void> {
    // Same SemanticEvent shape when another participant is streaming.
  }
}
```

`setStreaming(true)` on a model without `supportStreaming` throws before the API is called.

When streaming is off, the runner yields **`ContextItem`s only** (`ReasoningItem`, `FunctionCallItem`, `ModelMessageItem`) — no semantic events on the bus. See [Core concepts](/docs/concepts#messages-contextitems-and-semanticevents) for how the three event kinds relate, [Generators](/docs/generators) for custom runners, and [OpenResponses](/docs/open-responses) for how completed items map to the provider spec.
