This walkthrough mirrors the example in the [Mozaik README](https://github.com/jigjoy-ai/mozaik): create an `AgenticEnvironment`, `join` a `BaseHuman` and a `BaseAgent`, and trigger their capabilities so they produce events into the environment in parallel.

## Full example

```ts
import {
  AgenticEnvironment,
  BaseAgent,
  BaseHuman,
  OpenAIInferenceRunner,
  DefaultFunctionCallRunner,
  Gpt54Mini,
  ModelContext,
} from '@mozaik-ai/core';

const environment = new AgenticEnvironment();

const human = new BaseHuman();
const agent = new BaseAgent(
  new OpenAIInferenceRunner(),
  new DefaultFunctionCallRunner(),
);

human.join(environment);
agent.join(environment);

environment.start();

const context = ModelContext.create('demo');
const model = new Gpt54Mini();

// Both participants produce events in parallel — neither awaits the other.
human.sendMessage(environment, 'Hello');
agent.runInference(environment, context, model);
```

## What this is doing

1. **`AgenticEnvironment`** — An event bus for messages and `ContextItem`s. Once started, it fans every event out to every joined participant through the matching typed handler.
2. **`BaseHuman`** — Sends messages with `sendMessage(environment, text)`. Other participants receive them via `onMessage`.
3. **`BaseAgent`** — Wraps an `InferenceRunner` and a `FunctionCallRunner`. `runInference` and `executeFunctionCall` stream their output back into the environment.
4. **`ModelContext.create(projectId)`** — Allocates an empty context keyed by your own id (conversation, session, project). Participants typically append delivered events to the context they reason over.
5. **`human.sendMessage` / `agent.runInference`** — Capability methods. They return `Promise<void>` immediately and stream events in the background, so neither call blocks the other.

## Where events go

The human's message is delivered via `onMessage(message)` to every other participant. The agent's inference yields typed items, which the environment delivers via the matching handler — `onFunctionCall`, `onReasoning`, `onModelMessage` — and their `onExternal*` variants on every other participant.

A reactive agent typically overrides `onMessage` (record + run inference), `onFunctionCall` (execute the tool), and `onFunctionCallOutput` (feed the result back and run inference again). See the [Reactive Agent](/docs/reactive-agent) page for the full pattern.

New behaviors are added by **joining another participant**, not by editing the existing ones.

## What you'll need

The example uses the bundled runners:

- **`OpenAIInferenceRunner`** — calls the model and yields `ReasoningItem` / `FunctionCallItem` / `ModelMessageItem` (and semantic events when [streaming](/docs/streaming) is enabled).
- **`DefaultFunctionCallRunner`** — resolves `FunctionCallItem`s against registered tools.

For human input, call `sendMessage` from your UI or I/O layer when the user acts. Custom runner implementations are covered on the [Generators](/docs/generators) page.
