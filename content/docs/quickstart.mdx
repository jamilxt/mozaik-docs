This walkthrough mirrors the example in the [Mozaik README](https://github.com/jigjoy-ai/mozaik#non-blocking-participants): create an `AgenticEnvironment`, `join` a `BaseHumanParticipant` and a `BaseAgentParticipant`, and trigger their capabilities so they produce items into the environment in parallel.

## Full example

```ts
import {
  AgenticEnvironment,
  BaseAgentParticipant,
  BaseHumanParticipant,
  Gpt54Mini,
  ModelContext,
} from '@mozaik-ai/core';

const environment = new AgenticEnvironment();

const human = new BaseHumanParticipant(humanInputSource);
const agent = new BaseAgentParticipant(
  agentInputSource,
  inferenceRunner,
  functionCallRunner,
);

human.join(environment);
agent.join(environment);

environment.start();

const context = ModelContext.create('demo');
const model = new Gpt54Mini();

// Both participants produce items in parallel — neither awaits the other.
human.streamInput(environment);
agent.runInference(environment, context, model);
```

## What this is doing

1. **`AgenticEnvironment`** — A broadcast bus for `ContextItem`s. Once started, it fans every delivered item out to every joined participant's `onContextItem` callback.
2. **`BaseHumanParticipant`** — Wraps an `InputItemSource` so it can stream user/developer/system messages into the environment as they arrive.
3. **`BaseAgentParticipant`** — Wraps an `InputItemSource`, an `InferenceRunner`, and a `FunctionCallRunner`. Each capability streams its output items back into the environment.
4. **`ModelContext.create(projectId)`** — Allocates an empty context keyed by your own id (conversation, session, project). Participants typically append delivered items to the context they reason over.
5. **`human.streamInput` / `agent.runInference`** — Capability methods. They return `Promise<void>` immediately and stream items in the background, so neither call blocks the other.

## Where items go

Every item produced by any participant — a `UserMessageItem` from the human, a `ReasoningItem` or `ModelMessageItem` from the agent, a `FunctionCallItem` triggering a tool — is delivered to every joined participant via `onContextItem(source, item)`. New behaviors are added by **joining another participant**, not by editing the existing ones.

## What you'll need

The example assumes you already have:

- An `InputItemSource` that yields the user/developer/system messages your app produces.
- An `InferenceRunner` that calls the model and yields `ReasoningItem` / `FunctionCallItem` / `ModelMessageItem`.
- A `FunctionCallRunner` that resolves a `FunctionCallItem` against your tools and yields a `FunctionCallOutputItem`.

Implementations for all three are covered on the [Generators](/docs/generators) page.
