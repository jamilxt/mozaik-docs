This walkthrough mirrors the example in the [Mozaik README](https://github.com/jigjoy-ai/mozaik): create an `AgenticEnvironment`, `join` a `BaseHumanParticipant` and a `BaseAgentParticipant`, and trigger their capabilities so they produce events into the environment in parallel.

## Full example

```ts
import {
  AgenticEnvironment,
  BaseAgentParticipant,
  BaseHumanParticipant,
  Gpt54Mini,
  ModelContext,
} from '@mozaik-ai/core';

const environment = new AgenticEnvironment();

const human = new BaseHumanParticipant(humanInputSource);
const agent = new BaseAgentParticipant(
  agentInputSource,
  inferenceRunner,
  functionCallRunner,
);

human.join(environment);
agent.join(environment);

environment.start();

const context = ModelContext.create('demo');
const model = new Gpt54Mini();

// Both participants produce events in parallel — neither awaits the other.
human.streamInput(environment);
agent.runInference(environment, context, model);
```

## What this is doing

1. **`AgenticEnvironment`** — An event bus for messages and `ContextItem`s. Once started, it fans every event out to every joined participant through the matching typed handler.
2. **`BaseHumanParticipant`** — Wraps an `InputStream` so it can stream messages (strings) into the environment as they arrive.
3. **`BaseAgentParticipant`** — Wraps an `InputStream`, an `InferenceRunner`, and a `FunctionCallRunner`. Each capability streams its output back into the environment.
4. **`ModelContext.create(projectId)`** — Allocates an empty context keyed by your own id (conversation, session, project). Participants typically append delivered events to the context they reason over.
5. **`human.streamInput` / `agent.runInference`** — Capability methods. They return `Promise<void>` immediately and stream events in the background, so neither call blocks the other.

## Where events go

The human's input stream yields strings, which the environment delivers via `onMessage(message)` to every other participant. The agent's inference yields typed items, which the environment delivers via the matching handler — `onFunctionCall`, `onReasoning`, `onModelMessage` — and their `onExternal*` variants on every other participant.

A reactive agent typically overrides `onMessage` (record + run inference), `onFunctionCall` (execute the tool), and `onFunctionCallOutput` (feed the result back and run inference again). See the [Reactive Agent](/docs/reactive-agent) page for the full pattern.

New behaviors are added by **joining another participant**, not by editing the existing ones.

## What you'll need

The example assumes you already have:

- An `InputStream` that yields the messages your app produces (`async *stream(): AsyncIterable<string>`).
- An `InferenceRunner` that calls the model and yields `ReasoningItem` / `FunctionCallItem` / `ModelMessageItem`.
- A `FunctionCallRunner` that resolves a `FunctionCallItem` against your tools and yields a `FunctionCallOutputItem`.

Implementations for all three are covered on the [Generators](/docs/generators) page.
