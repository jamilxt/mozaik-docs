This walkthrough mirrors the example in the [Mozaik README](https://github.com/jigjoy-ai/mozaik/blob/development/README.md#full-example): define a **tool**, wire an **`AgentRuntime`** with hooks, and call **`agent.run(...)`** on a typed **`Context`**.

## Full example

```ts
import {
  Agent,
  AgentRuntime,
  HookId,
  Context,
  DeveloperMessage,
  Gpt54Mini,
  InMemoryContextRepository,
  Tool,
} from '@mozaik-ai/core';

const weatherTool = new Tool({
  name: 'get_weather',
  description: 'Get the current weather for a city',
  parameters: {
    type: 'object',
    properties: { city: { type: 'string' } },
    required: ['city'],
  },
  invoke: async ({ city }) => ({ temperature: '22°C', condition: 'sunny' }),
});

const runtime = new AgentRuntime();

runtime.on(HookId.BEFORE_INFERENCE, async (ctx) => {
  console.log(`[step ${ctx.execution.stepCount}] calling model...`);
});

runtime.on(HookId.AFTER_FUNCTION_CALL, async (ctx) => {
  console.log('tool result:', ctx.functionCallOutput);
});

const agent = new Agent(runtime);

const model = new Gpt54Mini([weatherTool]);
const context = Context.create('demo').addItem(
  DeveloperMessage.create('You are a weather assistant.'),
);

const repo = new InMemoryContextRepository();
await repo.save(context);

await agent.run("What's the weather like in Tokyo?", model, context);
```

## What this is doing

1. **`Tool`** — Describes a capability the model can invoke. Mozaik hands the tool's JSON schema to the provider and runs `invoke` when the model emits a `FunctionCall`.
2. **`AgentRuntime`** — Orchestrates the agent loop. Register callbacks with `runtime.on(HookId.X, cb)` to observe every state transition.
3. **`Agent`** — A thin wrapper around a runtime with overridable lifecycle methods. See [Agents & visitors](/docs/agents) for subclassing patterns.
4. **`Context.create(projectId)`** — Allocates an empty context keyed by your own id (conversation, session, project). Append `DeveloperMessage` / `UserMessage` items as you go.
5. **`agent.run(userInput, model, context)`** — Drives the loop until a final `ModelMessage` is produced (or an error is surfaced through `HookId.ON_ERROR`).
6. **`InMemoryContextRepository`** — Handy for demos; implement `ContextRepository` yourself for Postgres, Redis, S3, etc.

## What happens under the hood

The loop is a finite state machine: the runtime calls the model, handles any requested `FunctionCall`s by executing their tools, feeds results back as `FunctionCallOutput`, and terminates on the first `ModelMessage`. The full diagram and hook catalog live on the next page.
