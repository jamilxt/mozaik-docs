The **agent loop** is a finite state machine that drives a multi-step inference cycle. Each execution moves through states until it reaches a terminal condition.

## State machine

<Mermaid chart={`stateDiagram-v2
  [*] --> INFERENCE_PENDING
  INFERENCE_PENDING --> FUNCTION_CALL_PENDING: model returned a function call
  INFERENCE_PENDING --> MODEL_MESSAGE_RECEIVED: model returned a message
  FUNCTION_CALL_PENDING --> INFERENCE_PENDING: tool executed, feeding output back
  MODEL_MESSAGE_RECEIVED --> [*]: execution complete
`} />

The loop starts in **`INFERENCE_PENDING`**, calls the configured provider, and branches:

- If the model returns a **`FunctionCall`**, the runtime transitions to **`FUNCTION_CALL_PENDING`**, executes the matching `Tool`, appends a **`FunctionCallOutput`** to the context, and loops back for another inference.
- If the model returns a text message, it transitions to **`MODEL_MESSAGE_RECEIVED`** and the execution completes.

## Execution

An **`Execution`** object tracks:

- The current state.
- `stepCount` — how many loop iterations have happened.
- The transition history.
- Terminal status: `RUNNING`, `COMPLETED`, or `FAILED`.

Hooks receive the current `Execution` via `ctx.execution`, which is useful for step-aware logging, rate limiting, or cutting off runaway loops.

## Hooks

Every state transition exposes **before** and **after** hooks. Register callbacks on an `AgentRuntime` with `.on(hookId, callback)`:

```ts
import { AgentRuntime, HookId } from '@mozaik-ai/core';

const runtime = new AgentRuntime();

runtime.on(HookId.BEFORE_INFERENCE, async (context) => {
  console.log('About to call the model...');
});

runtime.on(HookId.AFTER_INFERENCE, async (context) => {
  console.log('Model responded:', context.inferenceResponse);
});

runtime.on(HookId.AFTER_FUNCTION_CALL, async (context) => {
  console.log('Tool executed:', context.functionCallOutput);
});

runtime.on(HookId.ON_ERROR, async (context) => {
  console.error('Agent failed:', context.error);
});
```

### Hook catalog

| Hook | Fires |
| --- | --- |
| `BEFORE_INFERENCE` | Before the model is called. |
| `AFTER_INFERENCE` | After the model responds. |
| `BEFORE_FUNCTION_CALL` | Before a tool is invoked. |
| `AFTER_FUNCTION_CALL` | After a tool returns. |
| `BEFORE_MODEL_MESSAGE` | Before the final message is received. |
| `AFTER_MODEL_MESSAGE` | After the final message is received. |
| `ON_ERROR` | When any state handler throws. |

### Hook context

Each callback receives a `RuntimeContext` with the same fields the FSM uses internally, including:

- `context.execution` — the `Execution` describing the current run.
- `context.inferenceResponse` — present after inference.
- `context.functionCallOutput` — present after a tool returns.
- `context.error` — populated when `ON_ERROR` fires.

Use hooks for cross-cutting concerns (telemetry, persistence, guardrails). Prefer subclassing [`Agent`](/docs/agents) when the logic is part of the agent's own behavior.
